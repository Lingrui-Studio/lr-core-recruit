# 课题二：ABI 与跨语言调用

## 引入

你可能已经听说过，不同编程语言所写的程序性能差异是非常大的，比如下面这张图展示了不同编程语言计算斐波那契数的表现：

![fabonacci performance](https://developer.qcloudimg.com/http-save/yehe-6490225/7ddb0270ec6eaac4e21d2d52990e6591.png)

可以看到最快的 C 语言仅需 0.40s（Clang 编译，O3 优化）；而大家常用的 Python 缺需要 29.00s。超过 50 倍的差距！究其原因——像 C 这样的编译型语言会直接编译为机器能运行的机器码形式，例如 Linux 中的 ELF 文件（`gcc main.c` 生成的 `a.out` 等）和 Windows 中的 EXE 文件；而 Python 这样的解释型语言则是由 Python 虚拟机在运行时将它们解释为虚拟机命令，再转为机器码执行，就相当于多了一个“转译层”，这当然是由性能损失的。

如今主流的所谓“高性能”组件/应用基本都是由 C/C++ 这类编译型语言实现的，上层再改为 Python 这类的解释型语言以加速开发流程。[PyTorch](https://github.com/pytorch/pytorch) 就是一个典型例子，作为 Python 深度学习框架中的扛把子，底层却是 C++ 写的（以及少量 C 和 Cuda），Python 实际上只是胶水层。

到此，我们再提出一个问题——那 C/C++ 就是最“底层”的语言了吗？其实不是的，在课题一中我们已经学习了汇编，自然知道 C/C++ 最终还是要被编译为汇编语言然后是机器语言，并且汇编语言对硬件的控制能力还要强于 C/C++。例如你可以在汇编语言中精确控制每个寄存器存什么东西干什么事儿，但这在 C/C++ 这类“高级语言”中却是不可能的，这也是为什么像 [FFmpeg](https://github.com/FFmpeg/FFmpeg) 和 [Linux](https://github.com/torvalds/linux) 这样的项目中汇编能仅次于 C 语言。

好了，到这里我们总算可以提出本课题最核心的问题了——**多种语言是如何协作的？**在基于 C 的操作系统上，其他语言又是如何调用其接口的？这就是 **ABI（Application Binary Interface，应用二进制接口）** 它不属于任何一门语言，却是所有语言能在同一台机器上协作的底线。

## 学习要求

- 学习基本的汇编语言，统一要求 x86 Linux 环境，AT&T 格式
- 学习汇编中的栈与栈寄存器、 `call` 和 `ret` 指令、如何传参和返回值，并了解各个寄存器分别是调用者保存的还是被调用者保存的

## 课题任务

- **手写汇编函数，在 C 里调用**
  实现一个汇编版的 `get_str_len` 求字符串长度
- **上下文切换：`save_context` 与 `switch_context`**
  用汇编保存和恢复寄存器，在 C 里测试。这是理解协程、线程切换乃至操作系统调度的最小切口，也是本课题的核心。
- **C 给 Python 打工：ctypes**
  用 C 实现某个计算密集的函数，编译成共享库，在 Python 中通过 `ctypes` 调用，与 Python 原生实现比较性能。做完这个，你大概就能明白 PyTorch 为什么"表面是 Python，底下是 C++"了。
